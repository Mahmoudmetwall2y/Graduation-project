## Model 1: PCG Heart Sound Classifier (XGBoost)

| Property | Value |
|---|---|
| **File** | `models/model1_xgboost/xgboost_model.pkl` (1.7 MB) |
| **Scaler** | `models/model1_xgboost/scaler.pkl` (14 KB) |
| **Label encoder** | `models/model1_xgboost/label_encoder.pkl` (455 B) |
| **Algorithm** | XGBoost gradient-boosted trees |
| **Task** | Multi-class classification of heart sound recordings |
| **Output classes** | Normal, Murmur, Artifact, Extrahls |
| **Input feature** | MFCC + spectral features extracted from PCG audio at 22,050 Hz |
| **Input signal** | PCG audio captured at 22,222 Hz, resampled to 22,050 Hz by inference |

### Known Limitations

- Trained on a specific dataset; performance on unseen patient populations is unknown.
- PCG hardware captures at 22,222 Hz (timer resolution). After the audit fix, inference
  resamples to 22,050 Hz correctly before feature extraction.
- Murmur detection is gated through this model: CNN severity (Model 2) only runs if
  this model predicts "Murmur".
- Signal artifacts (patient movement, electrode noise) can produce false positives.

## Model 2: Murmur Severity CNN (Multi-Output)

| Property | Value |
|---|---|
| **File** | `models/model2_cnn_severity/best_model.keras` (13.2 MB) |
| **Config** | `models/model2_cnn_severity/config.json` |
| **Label encoders** | `encoder_location.pkl`, `encoder_timing.pkl`, `encoder_shape.pkl`, `encoder_grading.pkl`, `encoder_pitch.pkl`, `encoder_quality.pkl`, `encoder_label.pkl` |
| **Algorithm** | Convolutional Neural Network |
| **Task** | Multi-output murmur characteristic classification |
| **Output heads** | location, timing, shape, grading, pitch, quality |
| **Input** | Mel spectrogram of PCG signal (cropped to 10 seconds) |
| **Gating** | Only runs if Model 1 predicts "Murmur" |

### Known Limitations

- Multi-head output assumes a single dominant murmur. Complex presentations may be misclassified.
- Grading (Levine scale) and location (auscultation site) require correct stethoscope placement.
  Hardware does not enforce placement — results depend on examiner technique.
- The model was not tested on pediatric populations.

## Model 3: ECG Arrhythmia Classifier (BiLSTM)

| Property | Value |
|---|---|
| **File** | `models/model3_bilstm_ecg/bilstm_model.keras` (2.8 MB) |
| **Label encoder** | `models/model3_bilstm_ecg/label_encoder.pkl` |
| **Config** | `models/model3_bilstm_ecg/config.json` |
| **Algorithm** | Bidirectional Long Short-Term Memory (BiLSTM) |
| **Training data** | MIT-BIH Arrhythmia Database (PhysioNet) |
| **Task** | AAMI EC57 5-class arrhythmia classification |
| **Output classes** | N (Normal), S (Supraventricular Ectopic), V (Ventricular Ectopic), F (Fusion), Q (Unknown) |
| **Required input rate** | **360 Hz** (MIT-BIH recording rate) |
| **Required window size** | **300 samples** (0.833 seconds at 360 Hz) |
| **Window stride** | 150 samples (50% overlap) |
| **Max windows per session** | 12 |
| **Model input shape** | `(batch, 300, 1)` |

### Critical Configuration

The inference service must have these environment variables set correctly:

```bash
ECG_SAMPLE_RATE=360   # Do NOT change — model trained on MIT-BIH 360 Hz
ECG_WINDOW_SIZE=300   # Do NOT change — model input shape is (batch, 300, 1)
```

The inference service automatically resamples the ESP32 500 Hz capture to 360 Hz
using `scipy.signal.resample` before windowing.

### Known Limitations

- Trained on MIT-BIH MLII lead configuration. The AD8232 ECG sensor captures a
  modified Lead I / Lead II equivalent — minor morphology differences may affect accuracy.
- 5-class AAMI taxonomy is a research classification. Clinical interpretation requires
  a cardiologist reviewing the full ECG trace, not just this automated prediction.
- Lead-off detection (AD8232 LO+ / LO- pins) will trigger `preflight_failed` and abort
  the session. Ensure proper electrode placement before recording.
- Short sessions or noisy ECG may produce fewer than 3 windows, reducing classification confidence.

## Demo Mode Predictions

When `ENABLE_DEMO_MODE=true`, all three models return **deterministic mock values**
instead of real predictions. Every mock prediction includes `"demo_mode": true`
in the database record. The dashboard displays predictions with a warning tone
when `demo_mode` is true.

**Real inference mode** (production): `ENABLE_DEMO_MODE=false` (default after audit fix).
