# AscultiCor MQTT Contract

This document is the authoritative reference for every MQTT topic, payload format, and
access-control rule used in the AscultiCor system. Both the ESP32 firmware and the
Python inference service must conform exactly to these specifications.

---

## 1. Topic Naming Convention

All topics follow one of two patterns:

```
Device-level:   org/{orgId}/device/{deviceId}/{suffix}
Session-level:  org/{orgId}/device/{deviceId}/session/{sessionId}/{suffix}
```

- `orgId` and `deviceId` are lowercase UUID v4 strings.
- `sessionId` is a UUID v4 generated by the inference service at session start.
- Topics are case-sensitive.

---

## 2. Topic Reference Table

| Topic suffix | Direction | QoS | Retain | Payload type | Publisher |
|---|---|---|---|---|---|
| `/status` | Device → Inference | 1 | Yes (LWT) | JSON | ESP32 |
| `/session/{id}/meta` | Device → Inference | 1 | No | JSON | ESP32 |
| `/session/{id}/pcg` | Device → Inference | 0 | No | Binary PCM int16 LE | ESP32 |
| `/session/{id}/ecg` | Device → Inference | 0 | No | Binary int16 mV | ESP32 |
| `/session/{id}/heartbeat` | Device → Inference | 0 | No | JSON | ESP32 |
| `/control` | Dashboard/Inference → Device | - | No | JSON | Dashboard |

**QoS rationale:**
- Data streams (PCG, ECG, heartbeat) use QoS 0 — highest throughput, no retransmit overhead.
  Dropped packets are tolerable in a streaming context.
- Control messages (meta, status) use QoS 1 — guaranteed delivery matters for session lifecycle.
- Status uses `retain=true` so a new subscriber immediately gets the device state.

## 3. PCG Binary Payload

The PCG stream is raw ADC data from the MAX9814 microphone, packed as signed 16-bit
little-endian integers.

| Field | Value |
|---|---|
| Encoding | PCM signed 16-bit little-endian (int16 LE) |
| **Actual hardware sample rate** | **22,222 Hz** (1 MHz timer / 45 ticks) |
| Declared `sample_rate_hz` in `start_pcg` meta | 22,222 (after firmware audit fix) |
| Samples per MQTT message (chunk size) | 512 |
| Bytes per MQTT message | 1,024 |
| DC offset removal | Sample = raw ADC - 2048 (firmware) |
| Inference normalization | Divide by 32,768 → float32 in [-1.0, 1.0] |
| Inference resample | librosa.resample: 22,222 Hz → 22,050 Hz |

> **Historical note:** Before the audit fix, firmware published `sample_rate_hz = 22050`
> (from `PCG_SAMPLE_RATE` define) even though the timer actually runs at 22,222 Hz.
> This caused inference to skip resampling. The fix publishes `1000000 / 45 = 22222`.

## 4. ECG Binary Payload

The ECG stream is ADC data from the AD8232 sensor, converted to millivolt integers.

| Field | Value |
|---|---|
| Encoding | Signed 16-bit little-endian (int16) |
| Hardware sample rate | 500 Hz (1 MHz timer / 2000 ticks) |
| Declared `sample_rate_hz` in `start_ecg` meta | 500 |
| Samples per MQTT message (chunk size) | 500 (1 second of data) |
| Bytes per MQTT message | 1,000 |
| Inference normalization | Divide by 32,768 → float32 |
| Inference resample | scipy.signal.resample: 500 Hz → 360 Hz (MIT-BIH target) |
| BiLSTM input windows | 300 samples, stride 150, max 12 windows per session |

## 5. JSON Payload Schemas

### `/status` — Device Status

```json
{
  "status":           "online",
  "ip":               "192.168.1.42",
  "rssi":             -58,
  "firmware_version": "1.2.0",
  "free_heap":        245680
}
```

LWT message sets `status = "offline"`.

### `/session/{id}/meta` — Session Lifecycle Events

```json
{
  "type":        "start_pcg",
  "session_id":  "uuid",
  "device_id":   "uuid",
  "timestamp_ms": 123456,

  // Additional fields for start_pcg:
  "sample_rate_hz":      22222,
  "format":              "pcm_s16le",
  "channels":            1,
  "chunk_samples":       512,
  "target_duration_sec": 15,
  "microphone":          "MAX9814",
  "gain_db":             60,
  "valve_position":      "AV"
}
```

**All meta `type` values:**

| type | Meaning |
|---|---|
| `start_pcg` | PCG recording starting |
| `end_pcg` | PCG recording complete |
| `start_ecg` | ECG recording starting |
| `end_ecg` | ECG recording complete |
| `preflight_ok` | Signal quality check passed |
| `preflight_failed` | Signal quality check failed (session aborted) |
| `warning_pcg_overflow` | ISR dropped audio buffers — signal quality degraded |

### `/session/{id}/heartbeat` — Device Health

```json
{
  "uptime":    12500,
  "free_heap": 245680,
  "rssi":      -58
}
```

### `/control` — Commands to Device

```json
{ "command": "start" }
{ "command": "stop" }
{ "command": "reboot" }
```

## 6. ACL (Access Control) Model

Every device is assigned a unique MQTT username and password via the bootstrap endpoint.

| Principal | Permissions |
|---|---|
| Per-device user | Read/write `org/{its_org_id}/device/{its_device_id}/#` only |
| Inference admin user | Read/write `org/#` (all orgs — required for multi-tenant inference) |
| Anonymous | **DENIED** — `allow_anonymous false` in mosquitto.conf |

ACLs are hot-reloaded every `MQTT_SYNC_INTERVAL_SEC` seconds (default 15 s) via
`SIGHUP` to the Mosquitto process — no restart required when a new device is added.

Password hashing: PBKDF2-SHA512, 101 iterations, with a per-deployment pepper set
via the `MQTT_DEVICE_PASSWORD_PEPPER` environment variable.

## 7. Topic Consistency Verification

The topic format is verified to be identical in:
- Firmware: `buildSessionTopic()` — lines 347–349 of `AscultiCor_esp32.ino`
